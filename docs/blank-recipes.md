# Blank recipes

Choose **Blank recipe**, the last source choice on Add recipe. Enter a recipe name. Categories, photos and favorites are optional at entry. Tap the heart to toggle your favorite, or hold it to choose household members using the same dialog as recipe viewing. Favorite choices are applied when the recipe is saved. The editor uses the same upload, camera, crop/rotate, cover selection and photo removal controls as other recipes. Parent and category choices are alphabetical and visible immediately. Leave category selection empty to have AI choose a parent and category from the name and save directly, without a review or confirmation dialog. Choosing a category yourself skips AI. Blank recipes never generate cooking content, recipe images or category artwork during creation.

Blank recipes appear in normal browsing, category browsing, search and favorite filters. **Filters → Blank recipes only** lists just blanks, combines with search/category scope and household favorite filters, and is reset by Clear and Apply. Offline saved libraries also honor the blank filter before pagination and do not substitute a nonblank family representative. Open one to edit its name/category/photos, delete it with the existing undo/trash behavior, or update individual and household favorites. The edit pencil opens the simplified name/category/photo editor.

A blank detail page identifies itself as **Blank recipe** in the app bar and shows the recipe name once in the page header, with its heart beside it. Edit and delete stay in the app bar. A dedicated picture area contains the existing gallery/edit control or an Add picture placeholder. Ingredient, method and source sections are omitted. Under **Import recipe**, Text, Website, File and Camera appear as equal-sized action buttons in a separate card. The page uses a 640-pixel maximum content width; buttons form two aligned columns or a single column for larger text on narrow screens. Selecting one opens that import form for the current blank. Review and save to fill the same recipe; its ID, favorites, existing pictures and categories are retained. Canceling or a failed import leaves the saved blank unchanged. Revision checks protect against concurrent edits. Regular imports continue to use their existing AI workflow.

Blank recipes use `source_type: blank` in the existing schema. The authenticated `POST /households/{id}/recipe-blank` endpoint returns an unsaved draft and the category catalog; the existing recipe save endpoint persists it. The backend requires a name and persists a category, either selected manually or classified with the existing hosted AI configuration. A failed classification leaves the draft available for retry or manual category selection; no partial recipe is saved. Blank recipes have no cooking content or nutrition. Neither share-link creation nor the public recipe webpage accepts a blank recipe. After import the recipe can be shared normally.

The entry page has a compact header, no redundant section shortcuts or Cancel button, and a 640-pixel maximum form width. Back navigation still protects unsaved edits; save progress explains automatic category selection. Photo upload, camera and editing keep the existing controls.

Validation: Flutter analysis; blank recipe/import/editor/favorite/photo/browser/search/sharing tests; PHP blank recipe fixtures plus existing relationship, favorite, sharing and photo checks. No app build or app deployment is part of this feature.

Visual validation uses `test/blank_recipe_detail_layout_test.dart` at 320, 373 and 960 pixels, including a long recipe name, large text, equal button sizes, offline state and callbacks. Optional `BLANK_RECIPE_PREVIEW_DIR` plus `FLUTTER_ROOT` renders local PNG previews from widget tests using SDK fonts. These previews do not build or publish the app.
